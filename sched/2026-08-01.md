## 二、按主题分组

### sched_ext（2 篇）
- **001** Tejun Heo 的 rescue execution 是 sched_ext 层级调度能力的关键补齐。当子调度器持有的 cid 无法覆盖任务亲和性时，此前只有两种结局：调度器被 repeat limit 驱逐，或任务 stall 到 watchdog。新机制用 `SCX_ENQ_RESCUE` 标记 + 内核受限带宽执行提供第三条路，并配套 `SCX_TASK_PROTECTED` 与过载归因驱逐。当日无 review。
- **002** Andrea Righi 的 idle mask 修复走到 v3，三个版本每一次改动都在回应 Kuba Piecuch，v3 反而是简化（复用已有 static key 而非新增）。接近可合入。

### CFS 唤醒路径 —— 当日焦点（2 篇 + 1 个第三方案）
三条路径在解决同一个问题，**这是本日最值得投入的讨论**：

| 方案 | 作者 | 切入点 | 数据 |
|---|---|---|---|
| 003 | Madadi Vineeth Reddy (IBM) | `select_idle_core()` 中让 waker CPU 计为 idle | POWER11 SMT8：hackbench 1-group +6~8%，producer_consumer 最高 +11%；但 thread-pipe 4-group **-8.8%** |
| 004 | Shubhang Kaushik (Ampere) | `!sched_smt_active()` 时直接偏好 waker CPU | Ampere Altra 非 SMT：perf bench sched pipe **+30%**（40 轮平均） |
| （第三方案） | K Prateek Nayak (AMD) | 下推进 `select_idle_sibling()`，以 `has_idle_core` 而非「有无 SMT」为判据 | SMT-2 上"轻度测试" +10% |

**关键争议**：Zhan Xusheng 对 003 提出，`select_idle_cpu()` 的 `for_each_cpu_wrap(cpu, cpus, target + 1)` 扫描顺序意味着——POWER 上 SMT 兄弟编号连续、恰好在 `target+1` 被最先命中；而 x86 常见布局兄弟在 `cpu + nr_cores`，扫描会先遇到其他 core，只要有一个全空闲就会先返回那个冷 core。**收益可能是 POWER 特化的**。作者当日未回应。

三套方案没有一套跑过跨平台横向对比，这是当前最缺的输入。

### 负载均衡与拓扑（2 篇）
- **005** ILB 不应跑在繁忙 SMT core 的空闲兄弟上（会挤占其算力）。v3 的剪枝已相当干净：有 fallback 之后遇到繁忙 CPU 即 `cpumask_andnot` 掉整个 `cpu_smt_mask()`。**但整个系列没有一个数字**——reviewer 们都在讨论「怎么让剪枝更快」，没人问「这个优化值多少」。
- **006** cache-aware scheduling 的 `migrate_llc_task` 约束在被动均衡→active balance 的异步边界上静默丢失，叠加 `can_migrate_task()` 中 `LBF_ACTIVE_LB` 的无条件 `return 1`，可能把任务搬离 preferred LLC。修复思路清晰但同样零证据；另注意该 patch 在 20:17 与 20:22 连发两封，需作者澄清。

### 抢占与工具（3 篇）
- **007** Boqun Feng 24-patch 系列中采样到 3 个 sched 相关：删 `__cant_sleep()` 的死参数、消除 `__cant_migrate()` 的有符号比较、为 arm64 打开 `HAS_SEPARATE_PREEMPT_RESCHED_BITS`（单行）。均为低风险，但作为跨架构大系列需多方协调。
- **008** `perf sched latency` 在无 tracepoint 样本时打印空表格的误导性问题，加上 ns/us/ms/s 自动单位换算。Namhyung Kim 的三条意见全是形式性的（拆 commit、squash、补 before/after 输出），方向已获认可。
- **010** typo 修复，但第二处改动疑似把 `memalloc_nfs_save()` 改成了 `memalloc_nfos_save()`，而正确写法是 `memalloc_nofs_save()`（可对照相邻行的 `memalloc_noio_save()`）。

### 电源管理交叉（1 篇）
- **009** 严格说属 `drivers/cpufreq`，纳入是因为触发条件完全依赖 `nohz_full` 调度隔离：performance policy 下 CPU 被钉在固定 pstate，但 `policy->cur` 随即被覆写为 `policy->min`；隔离 CPU 的 tick 关闭后 APERF/MPERF 采样永不刷新，于是永久通过回退路径上报错误的下限频率。
