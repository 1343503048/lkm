# sched: Lift cgroup update locking to core to prevent CFS/SCX divergence

## TL;DR
Michal Blaszczyk 修一个 CFS/SCX cgroup 参数「三视图发散」竞态：并发写 cpu.shares 等控制文件时，CFS 内部锁在调 SCX 回调前释放，允许多线程穿插，使 CFS 记录值、SCX 簿记、BPF 调度器三者拿到不同参数。v3 把锁上移到 core 层统一串行化。合入概率高。

## 背景与问题
`cpu_shares_write_u64()` 里 CFS 更新被 `shares_mutex`（fair.c 内部）串行化，但该锁在调用 `scx_group_set_weight()` 前释放；后者只拿读信号量 `scx_cgroup_ops_rwsem`。于是两个线程可并发评估并作用于 SCX 更新，导致 CFS、`tg->scx.weight`、BPF 调度器本身各自基于不同参数运行。同样竞态存在于 `tg_set_bandwidth()`、`cpu_idle_write_s64()`、`cpu_weight_write_u64()`、`cpu_weight_nice_write_s64()`。

## 技术方案
把 CFS 锁上移到 core 层写处理函数：在 `kernel/sched/core.c` 定义 `cpu_weight_mutex`，在 `cpu_shares_write_u64()` 等 core 写处理函数内用 `guard(mutex)(&cpu_weight_mutex)` 包裹，调用新增的 `_locked` 变体（如 `sched_group_set_shares_locked`），从而在 core 层同一把锁下原子执行 CFS 与 SCX 回调。fair.c 内的 `cfs_constraints_mutex` 相应上移/重命名。
