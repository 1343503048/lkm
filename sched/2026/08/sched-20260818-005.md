## TL;DR
本文为 **增量更新**，完整背景见 `sched-20260817-002`（compat.bpf.h peek/reenqueue 同步）。本日 Tejun 对该系列 patch 1（peek 版本门控）给出 review：指出门控逻辑本身 OK，但**描述与注释不准确**——`2f2ea7709266` 是 v7.1 新增、其修的是 v6.19/v7.0 上 `scx_bpf_dsq_peek()` 在非空 FIFO DSQ 上误返 NULL，而非 stale task 指针（`71d7847cad44` 在 v6.19 即随 peek API 一起 ship，每个有该 kfunc 的版本都有它）。要求更新描述/注释以准确反映门控所避免的问题，并去掉编辑遗留的悬空 ` *` 行。

## 背景与问题（延续）
08-17 系列 patch 1 把无锁 `scx_bpf_dsq_peek()` 门控在 kernel >= 7.1.0，注释称"其 lockless 实现可能返回 stale task_struct 指针"。Tejun 澄清：实际上 7.1 之前（v6.19/v7.0）该 kfunc 的问题是**在非空 FIFO DSQ 上误返 NULL**，而非 stale 指针；stale 指针问题（若存在）在 7.1 才由 `2f2ea7709266` 修复。因此"要求 >=7.1 以避免 stale 指针"的表述不准确——门控实际上是为了避免 v6.19/v7.0 的 NULL 误返。

## 技术方案讨论（增量）
- 门控本身（>=7.1.0 走 lockless peek，否则 fallback `bpf_iter_scx_dsq`）Tejun 认可。
- 需修正：描述与注释把"避免 stale 指针"改为"避免 v6.19/v7.0 上非空 FIFO DSQ 误返 NULL"。
- 去除编辑遗留的悬空 ` *` 行（注释块闭合前多余行）。
