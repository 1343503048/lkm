## 一、重要补丁系列（Patch Series）

### 1. sched_ext：使代理执行（proxy execution）与 sched_ext 兼容 — v9 🔥
- **作者**：Christophe Stump（基于 John Stultz 早期工作）
- **邮件**：UID 354（封面）→ 355–368（共 15 封，14 个补丁）
- **核心问题**：当前 `CONFIG_SCHED_PROXY_EXEC` 与 `CONFIG_SCHED_CLASS_EXT` 在构建期互斥，发行版无法同时启用。代理执行会把「donor」任务的调度上下文捐赠给互斥锁持有者，而 sched_ext 的 BPF 调度器通过 DSQ 自行派发，二者对「谁在运行」的认知会不一致。
- **设计方案**：以**可选 per-scheduler 能力**实现 —— BPF 调度器设置 ops 标志 `SCX_OPS_ENQ_BLOCKED`，保留被互斥锁阻塞的 donor 可运行，并通过 `ops.enqueue()` 携带 `SCX_ENQ_BLOCKED` 接收。
- **关键补丁**：
  - `sched/core: Avoid false migration warning for proxy donors`（01）—— donor 迁移禁用时上下文移动不触发误报迁移警告
  - 在 `__schedule()` 三处让 sched_ext 观测 donor/执行上下文拆分（360）
  - 解耦 reject DSQ 仅用于 sub-scheduler cap 失败的限制（362）
  - 用 `SCX_OPS_ENQ_BLOCKED` 接收 blocked proxy donors 并加 selftest（368）
  - 移除 `SCHED_PROXY_EXEC` 对 `!SCHED_CLASS_EXT` 的依赖，允许二者同时启用（367）
  - scx_qmap 加 `-B` 选项启用 blocked-donor 排队（359）
- **状态**：已发布 v9，**暂无 Reviewed/Acked/Tested 标签**（周日无评审回复）。

### 2. sched_ext：限制 per-task 重入队（reenqueue）次数并驱逐所属调度器 — v1/v2
- **作者**：Tejun Heo `<tj@kernel.org>`
- **邮件**：UID 476（v1 补丁）、483（v1 封面）、770（v2 或 review 回复）
- **问题**：cap 拒绝没有重复上限，故障调度器可让任务在 reject/reenqueue 间无限循环；`reenqueue irq_work` 会抢占 timer 向量，阻塞包括 stall 检测在内的一切，直到 NMI hardlockup 触发。
- **方案**：用单一 per-task 计数器 `reenq_cnt`（在 `scx_do_enqueue_task()` 每次 `SCX_ENQ_REENQ` 时递增，任务被选中运行时在 `clr_task_runnable()` 清零）统一约束所有重入队；超过 `SCX_REENQ_MAX_REPEAT` 则驱逐所属调度器（`SCX_EXIT_ERROR_REENQ`）。`SCX_EV_REENQ_LOCAL_REPEAT` 改为 `SCX_EV_REENQ_REPEAT`。
- **状态**：已发布并由 Andrea Righi 于 7/22 评审，7/26 有后续讨论。

### 6. sched_ext/for-7.2-fixes：allowed_cpus selftest 修复 + 标记 waker CPU 为 busy — **已合入** ✅
- **作者**：Andrea Righi / Kuba Piecuch
- **邮件**：UID 734（Kuba 原补丁说明）、744/742（Andrea 的修订版）
- **问题**：SCX 内置空闲 CPU 跟踪在启用后与真实空闲态可能不同步；`SCX_WAKE_SYNC` 场景下 waker CPU 仍被标记 idle，导致 `allowed_cpus` selftest 报 "CPU 0 should be marked as busy"。
- **方案（Andrea 版）**：改为校验稳定不变量（local CPU 运行非 idle 上下文时不得出现在 idle mask），同时校验请求域与任务亲和性；并用 bootstrap 阶段在每个在线 CPU 跑任务以正确初始化 idle mask。
- **状态**：Andrea 的修订版已应用。
